# World and chunk pipeline

Bedriox generates authoritative world state independently from the Bedrock network palette, then translates it only while encoding an outgoing chunk.

## Generation and ownership

`WorldMetadata` identifies the logical level and seed. `WorldSpawnResolver` supplies the level's safe spawn unless all three configured spawn coordinates override it. A provider-backed `World` owns a `WorldGenerator`, bounded `ChunkRepository`, and `WorldProvider`. Immutable cell replacement creates a new authoritative chunk revision and marks it dirty. Providerless worlds retain the bounded process-local override store only as an explicit ephemeral compatibility path.

`WorldGeneratorFactory` resolves the persisted `default` or `flat` identity. Both generators can generate any requested coordinate deterministically. They resolve canonical states through `BlockStateRegistry` and store dense process-local `InternalBlockStateId` values in `SubChunk` and `Chunk` objects. Those IDs have no stable meaning outside the process and must never be persisted, configured, logged as a public contract, or written directly to the wire. The LevelDB provider persists canonical block-state name and property NBT and resolves fresh process-local IDs while loading.

RFC 0023's worker boundary uses a versioned, checksummed, byte-bounded chunk transfer. It carries coordinates, revisions, dirty and finalization state, canonical block-state keys, section palettes and indices, and canonical biome palettes and indices. PHP object serialization, process-local block-state IDs, providers, worlds, players, sessions, encryption state, and sockets never cross that boundary. The matching generation request is separately versioned and bounded; each long-lived worker initializes the admitted immutable Data registry once, keeps a bounded set of generators keyed by generator version and world seed, verifies the requested overworld contract, and returns the same canonical transfer bytes as synchronous generation. Missing chunks are deduplicated and generated by the managed core pool when workers are enabled. The main loop validates the coordinate and request generation before installing the result. Saturation, worker failure, or `workers.core-count=0` uses the byte-equivalent synchronous generator without changing authoritative ownership.

An installed immutable revision then follows the complete worker-side preparation path. Block and biome storages retain validated X-Z-Y packed word arrays alongside their authoritative byte-indexed views. The preparation snapshot carries canonical palettes and those bounded packed words, deduplicating repeated biome sections instead of expanding every cell across IPC. A worker translates each palette entry once, writes the existing word arrays through Protocol, frames the `LevelChunk`, builds the batch, and applies negotiated zlib compression. Long-lived workers reuse one immutable admitted registry and translation context. The result is a compressed clear envelope containing no session cipher state. The main process accepts it only for the exact world incarnation, chunk object and revision, protocol, registry hash, serializer version, and compression profile that requested it. Session encryption and RakNet delivery remain on the authoritative process.

The initial flat profile is bedrock at Y=60, dirt at Y=61 and Y=62, grass at Y=63, and air elsewhere. The world spawn places the player's feet above that surface.

The default profile combines deterministic warped climate fields with interpolated three-dimensional density to form coastlines, lowlands, mountain ranges, overhangs, valleys, rivers, oceans, aquifers, and cave networks across chunk boundaries. Base terrain density is retained separately from carved density: open terrain fills continuously to sea level while carved underground spaces continue to use aquifer and deep-lava rules. The complete pinned Bedrock biome registry is admitted; the Overworld resolver selects ocean, coast, river, lowland, forest, dry, cold, mountain, mutated, and vertical cave families while Nether and End identities remain available to their future dimensions. Surface rules add cold-region ice, terracotta, podzol, mud, mycelium, snow, aquatic flora, coral, ores, cave decoration, and biome-specific vegetation. Deterministic cross-chunk population adds villages, temples, ocean ruins, swamp huts, ruined portals, mineshafts, dungeons, geodes, and strongholds without depending on chunk request order. The terrain surface is captured before decoration; structures anchor to that immutable height field before vegetation runs, and trees and plants require admitted substrates plus replaceable volume. This prevents paths and foundations from treating foliage as terrain and prevents later vegetation from overwriting structures. Generator pillars select exact canonical axis variants, making tree trunks vertical; authoritative player placement selects the pillar axis from the clicked face. Source fluids occupy only the primary block layer and are non-solid for collision. Spawn selection searches a bounded area for dry terrain with two air blocks of headroom. The algorithm is Bedriox-defined and does not promise Minecraft seed parity.

## Persistence

The provider is consulted before generation. An existing chunk is decoded and cached; only a definite missing result invokes the configured generator. Corrupt, unsupported, or unreadable data fails explicitly and is never treated as an empty coordinate that may be regenerated.

`LevelDbWorldProvider` stores Mojang-compatible `level.dat` metadata, a repairable `levelname.txt` display-name mirror, and Bedrock LevelDB chunk records. `level.dat` is authoritative if the mirror is absent or stale. Persistent palettes use canonical block-state NBT, while chunk keys, subchunk records, biome palettes, height maps, and finalization state follow the supported Bedrock storage contract. Disk XZY palette order is translated explicitly to the world's internal coordinate order.

Generated and changed chunks remain dirty until their exact immutable revision is acknowledged by a successful provider write. Autosave scans past revisions already queued or in flight, so one slow coordinate cannot starve later dirty chunks. Autosave processes the oldest eligible dirty chunks first with the configured `chunk-saving.per-tick` bound whenever `level.autosave-interval-ticks` elapses. A dirty eviction candidate is saved before removal; a failed write or newer in-memory revision leaves it resident and dirty. Graceful close flushes every remaining dirty chunk and world metadata before closing the provider.

## Cache and view scheduling

`ChunkRepository` loads or generates on demand and retains a bounded shared cache. Active session views lease their chunks so an in-use column cannot be evicted. Configuration must reserve enough capacity for every maximum-size player view.

When the final lease is released, the coordinate enters a monotonic grace queue. A new retain cancels that candidate. Each tick examines only the configured number of due candidates and also yields at an elapsed-time boundary. Clean, unretained chunks are removed with all repository bookkeeping; dirty chunks first submit an exact immutable revision and unload only after the matching acknowledgement. Memory pressure may increase the bounded examination count but cannot bypass retention or durability rules.

The configured world-spawn chunk receives one idempotent world-lifetime lease through the non-blocking storage/generation path. Respawn destinations additionally receive temporary leases for the complete player collision footprint, including neighboring columns at chunk boundaries. Respawn remains pending until every required column is available, so collision grounding never falls back to a synchronous provider read behind queued chunk saves. Plugin-selected coordinates are loaded exactly as supplied and are not relocated by this lifecycle rule.

Each play session owns one `ChunkViewManager`. It clamps the requested radius, computes a nearest-first square, queues missing coordinates, and releases coordinates that leave the retained area. The configured hidden prefetch ring is retained outside the visible square. Visible work always has priority; the ring is prepared only after every visible coordinate is ready, and prefetched columns are never sent before they enter the negotiated view. Crossing a 16-by-16 block boundary recenters both areas, rebuilds unsent delivery priority around the new authoritative center, promotes already prepared edge columns directly into the visible send queue, and schedules only newly missing coordinates. Old rear and lateral work cannot remain ahead of the current center merely because it entered the queue earlier.

Generation, preparation admission, and delivery have independent count limits. Preparation additionally yields at a main-thread time or transfer-byte boundary; ready delivery yields at a time or compressed-byte boundary. The staging queue stores coordinates rather than bytes. Before encryption the channel resolves the current authoritative chunk again and requires the prepared cache key and revision to match, so an intervening block or biome change cannot send stale terrain. Only ready compressed chunks enter session ordering; unresolved worker promises never sit in front of chat, command, inventory, or control packets.

`PreparedChunkCache` is shared by every compatible session. It deduplicates one in-flight task per complete identity and retains compressed clear envelopes under independent entry and byte limits with deterministic LRU eviction. Preparation uses a small worker-sized in-flight window rather than filling the global worker FIFO, allowing movement to redirect upcoming work promptly. Its compact projection transfer is distinct from the complete canonical chunk transfer used by generation and persistence; it contains only immutable data needed for the current wire projection. A new immutable chunk object or revision invalidates completed and pending work for that coordinate immediately. Late completion is ignored. Three failed attempts select the bounded synchronous serializer rather than disconnecting a healthy player. Closing the runtime cancels all remaining preparation tasks before the worker pool stops.

The configured spawn-radius square is delivered before `PlayerSpawn`. Remaining negotiated-view chunks continue afterward. Completed views remain idle until movement changes the center; they must not continually regenerate or resend their full set.

## Wire translation

`BlockNetworkTranslator` maps each internal canonical state to the active Data network runtime ID. `BedrockChunkPacketSerializer` translates each unique section palette once and passes the storage's pre-packed words to Protocol to encode complete columns for the current contract, including section palettes, air sections, biome data, height maps, coordinates, and bounded block entities. Production workers prepare and compress the same byte-equivalent representation; the main-thread serializer remains the bounded fallback and the authority for small block-event projections.

Biome palettes use Data's separate canonical `LevelChunk` runtime-ID registry. Definition-list ordering is never treated as a runtime ID, and every biome—including plains—uses the same bijective translation path in synchronous and worker serializers.

Translation happens only at this boundary. The generator must not import network IDs, and the serializer must not invent world state. Full streamed columns currently do not require client SubChunk requests; unexpected requests are validated and rejected by policy.

The version-one `default` pipeline derives independent seed channels for coordinate warping, continentalness, erosion, temperature, humidity, ridges, uplift, rivers, local detail, density, caves, aquifers, ores, vegetation, and structures. Regional coordinate sampling is cached under a fixed bound, while every feature anchor is derived from world coordinates and replayed into every intersecting chunk so generation order cannot change or clip the result.

`level.dat` stores the generator name and `BedrioxGeneratorVersion`. Missing version metadata is interpreted as version one for native compatibility. A stored version that the selected generator cannot reproduce is rejected before any missing chunk can be generated. During the current alpha, the version-one algorithm may be replaced in place and development worlds must be deleted before testing the replacement. Once the terrain contract is declared stable, later incompatible upgrades require a new explicit stored version rather than silently creating seams beside established terrain.

## Deferred streaming performance milestone

Packed projection transfer and worker-side packet preparation remove serialization from the critical main-thread path. Further work targets the supply of authoritative chunks rather than changing the proven wire format: measure storage lookup, generation, preparation, enqueue, acknowledgement, and delivery latency independently; pipeline bounded LevelDB reads; prioritize newly visible terrain over hidden work; add direction-aware prefetching; isolate or prioritize long generation tasks relative to packet preparation; and profile the default generator before optimizing its terrain stages. Retail qualification must include sustained movement into uncached terrain while preserving 20 TPS, bounded memory, deterministic terrain, and responsive chat and control traffic.

## Required invariants

- Every generated coordinate returns the same canonical cells for the same world definition.
- Generator output is independent of chunk request order and sign of the coordinates.
- Every built-in generated block has explicit gameplay and collision definitions.
- Structures use the captured terrain surface rather than post-decoration foliage, and vegetation requires an admitted substrate and replaceable volume.
- Every visible column contains the correct absolute chunk coordinates.
- Every internal state resolves through the active network palette before sending.
- Existing provider data is loaded before generation; storage failures never become implicit generation.
- Dirty chunks are acknowledged only after their authoritative revision is written successfully.
- Eviction and graceful shutdown cannot discard unsaved provider-backed changes.
- Every section and biome cell reconstructs semantically, not merely to an expected byte length.
- Generation, cache residency, queued packets, retained views, and per-tick work remain bounded.
- Hidden prefetch work never delays visible generation and never emits a chunk packet before visibility.
- Cache capacity accounts for every configured player view including its hidden prefetch ring.
- Movement releases departed columns and queues only newly visible ones.
- Matching players and requests share one prepared revision instead of repeating projection and compression.
- A prepared envelope is revalidated against the current authoritative immutable chunk before encryption.
- Unresolved chunk work cannot become a head-of-line barrier for unrelated player output.
- Failure and disconnect release every lease and pending payload.

When terrain is wrong, test generation, translation, serialization, scheduling, and delivery separately. Do not change registry values or transport framing to mask an unproven layer defect.
